Identifying Interaction Design and Functional Layout

Practical implementation of interaction design and functional layouts

Case study: Personal App — Complete Application (Notes, Habits, Calendar, Calculator, Life Tracker, Settings & Onboarding)

Submitted by: SAI CHANDAN KS (23MIS0115) Tools: Flutter 3.22+ · Dart 3.7+ · Provider · SQLite

1. Aim

To identify user requirements for a multi-feature personal application, design interaction prototypes for each module, and implement them with consistent placement, wording, and colour so the user can build an accurate mental model across all six modules — demonstrated through Personal App, a local-first Flutter application featuring rich-text notes, habit tracking, a calendar with events, a scientific calculator, a life tracker, and customizable settings with onboarding.

2. Objectives

  1. Understand the principles of interaction design and functional layout across multi-module applications.
  2. Translate user requirements into working design prototypes for each of the six modules (Activity 1).
  3. Apply consistency rules — button placement, label wording, colour scheme — across every screen in every module (Activity 2).
  4. Evaluate whether the resulting cross-module interface supports an accurate, predictable mental model.

3. Theory

3.1 Interaction Design Across Modules

Interaction design (IxD) focuses on the sequence of screens and states a user moves through to complete a task. In a multi-module app, IxD must ensure that each module has a clear entry point, predictable transitions, and consistent feedback. The Notes module uses a list-to-editor flow, Habits uses a dashboard-to-detail flow, Calendar uses a grid-to-event flow, Calculator uses a display-to-history flow, and Life Tracker uses an empty-to-dashboard flow.

3.2 Functional Layout

Each module arranges its elements to support its primary task: the Notes FAB creates notes, the Habits FAB adds habits, the Calendar FAB creates events, and the Calculator places digits and operators in a standard grid. The bottom navigation bar or navigation rail persists across all modules with the active tab highlighted.

3.3 Consistency Principles

Four concrete rules are applied across all six modules:

  • Placement consistency — FABs are always bottom-right. Search bars are top-left. Delete/destructive actions are always accessed via menus or confirmation dialogs.
  • Wording consistency — “Save”, “Cancel”, “Delete”, “Discard”, “Retry” use identical labels across modules.
  • Colour consistency — Blue = primary action, red = destructive, amber = warning, green = success. These meanings are preserved in all modules.
  • Icon consistency — The same icon set and symbol meanings are used throughout (trash = delete, + = create, search = find, etc.).

3.4 Cross-Module Mental Model

When placement, wording, colour, and icons stay consistent across modules, a user who learns the interface in Notes can correctly predict how Habits, Calendar, Calculator, Life Tracker, and Settings will behave. This reduces the learning curve from six independent modules to one transferable pattern.

6. Activity 2 — Apply and Verify Consistency

Consistency rules were applied once at the app level (via Material 3 theme, shared widgets, and a common design system) and reused across all six modules rather than implemented independently per module.

6.1 Consistency rules applied

Button Placement

FAB is always bottom-right across Notes, Habits, and Calendar. Delete actions are always accessed via confirmation dialogs. Save is always top-right. Cancel is always left, Confirm is always right in dialogs. Consistent across all 6 modules.

Label Wording

‘Save’, ‘Cancel’, ‘Delete’, ‘Discard’, ‘Retry’, ‘Apply’ never change across modules. Confirmation dialogs echo the verb: ‘Delete habit?’, ‘Clear all data?’. Consistent error messages use ‘Something went wrong’ with Retry.

Colour Scheme

Blue — primary action, FAB, active tab, save
Red — destructive (delete, discard, high priority)
Green — success, completion, low priority
Amber — warning, medium priority, caution
No colour is reused for a different meaning across modules.

Icon & Navigation Consistency

Search is always the leftmost icon in app bars. The create FAB is always bottom-right. The bottom NavigationBar (or NavigationRail on wide screens) uses an IndexedStack to preserve state. Icons use the same symbol set throughout (trash, +, back, search, settings gear).

6.2 How this builds a cross-module mental model

Because the same rules are reused across all six modules, the user needs to learn the interaction pattern only once. After using Notes, the user already knows:

  • The blue FAB creates new content (note, habit, event).
  • A red button means deletion (always confirmed via dialog).
  • Long-press opens selection mode for bulk actions.
  • Search always works the same way — real-time filtering at the top.
  • Theme and colour choices in Settings instantly apply to all modules.
  • The back arrow or swipe gesture always navigates to the previous screen.

7. Output / Result

The completed Personal App prototype implements all six modules within a single Flutter application sharing a common Material 3 design system. The app opens with a 5-page onboarding flow (first launch only), then presents six tabs via IndexedStack: Notes (rich text with colour/priority/trash), Habits (three tracking types with streaks), Calendar (month grid with events and recurrence), Calculator (basic + scientific with memory), Life Tracker (real-time dashboard), and Settings (appearance, notifications, data management).

The design system is configured once via Material 3’s theme system with a user-selectable color scheme seed, and every screen inherits the same placement, wording, and colour rules automatically.

7.1 Self-evaluation checklist

  • ✓ Is the primary action in the same position across all modules?
    Yes — FAB bottom-right in Notes, Habits, Calendar; Calculator uses display area consistently
  • ✓ Does the same action always use the same word?
    Yes — Save / Cancel / Delete / Discard / Retry / Apply identical across all 6 modules
  • ✓ Is each colour assigned exactly one meaning?
    Yes — Blue = action, Red = destructive, Green = success, Amber = warning — consistent in all modules
  • ✓ Can a user predict an unseen module from a seen one?
    Yes — Habits reuses FAB + search + selection patterns from Notes; Settings reuses dialog patterns
  • ✓ Does every loading/error state provide feedback and recovery?
    Yes — Loading spinner + Error state with Retry button in Notes, Habits, Calendar, Settings import
  • ✓ Is every destructive action protected by a confirmation dialog?
    Yes — Delete, Discard, Clear All Data, Reset Life Tracker all require explicit confirmation
  • ✓ Are both empty and populated states handled everywhere?
    Yes — Notes, Habits, Calendar, Life Tracker, Calculator history all have empty states with CTAs
  • ✓ Does the navigation persist across all modules?
    Yes — IndexedStack preserves all 6 tabs; NavigationRail on wide screens, NavigationBar on narrow

Annexure A — Selected UI/UX Ideas Integrated

Seven ideas from the reference design-thinking framework were integrated across the Personal App modules:

1. Progressive Onboarding with Skip

Module: Onboarding  |  5-page PageView introducing all features. Skip button visible on pages 1–4. Only shows on first launch via SharedPreferences flag. The Notes page introduces rich text editing before the user even opens the app.

2. Colour + Priority Visual Encoding

Module: Notes + Habits  |  Both modules use colour to convey meaning. Notes uses 14 colour presets + custom for visual distinction and 4 priority levels. Habits uses 12 colour presets per habit. Both use a shared custom HSV/Hex picker component.

3. Search with Real-Time Feedback

Modules: Notes, Habits, Calendar  |  All three modules implement the same search pattern: debounced text input at the top of the screen, real-time filtering, and both hit and no-result states with clear messaging.

4. Trash with Restore Safety Net

Module: Notes  |  Soft delete model with a dedicated Trash bottom sheet. Users restore individual items or permanently delete. Clear timestamps show deletion date. “Empty Trash” bulk action available.

5. Streak Tracking for Habit Motivation

Module: Habits  |  Current streak and best streak calculated from consecutive daily completions. Displayed in the Stats Card alongside the monthly completion percentage and progress bar. Drives daily engagement through the “don’t break the chain” effect.

6. Live Real-Time Counter

Module: Life Tracker  |  Uses a Stream.periodic timer to update elapsed time every second. All metrics (years, months, days, hours, minutes, seconds) update in real time on the dashboard, creating a compelling “clock” effect that encourages user return.

7. Live Theme Preview with Custom Color Picker

Module: Settings  |  The color seed picker shows a live SV gradient area with a hue slider and Hex input. The selected colour applies instantly to the Material 3 theme via colorSchemeSeed. Users see their changes in real time before committing.
